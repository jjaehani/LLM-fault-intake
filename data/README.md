# 데이터

모든 장비 목록, 증상 분류, 문장은 직접 만들었다. 실제 업체의 수리 내역, 고객 문의, 분류표, 장비 모델명은 쓰지 않았다.

## 파일

| 파일 | 내용 |
|---|---|
| `equipment.csv` | 접수 대상 장비 6종과 현장에서 부르는 다른 이름 |
| `taxonomy.csv` | 증상 분류표. 장비 > 묶음 > 세부 증상 3단계와 코드 |
| `dev.csv` | 프롬프트를 고칠 때 보는 조정용 문장 20개 |
| `holdout.csv` | 시험용 문장 12개. 프롬프트를 고칠 때 보지 않는다 |
| `symptoms.csv` | 1단계에서 쓴 기계 장비 문장 19개. 기록용으로 남겨 둔다 |

## 증상 분류표

장비마다 증상을 전원, 화면, 알람, 출력처럼 묶음으로 나누고, 묶음 안에 세부 증상을 둔다. 코드는 `장비-묶음-번호` 형식이다(예: `INV-ALM-01`은 인버터의 알람 묶음 첫 번째, 과전류 트립).

분류는 장비 종류별로 흔히 알려진 고장 양상을 바탕으로 정했다. 실제 접수 데이터로 검증한 분류가 아니라서, 데이터가 생기면 묶음과 세부 증상을 다시 나눠야 한다.

## 문장 파일의 열

| 열 | 내용 |
|---|---|
| id | 문장 번호 |
| type | `intake`(접수) 또는 `off_topic`(범위 밖 질문) |
| utterance | 접수자가 처음 보내는 문장 |
| equipment | 정답 장비. 문장에 없으면 비운다 |
| symptom | 정답 증상 |
| symptom_code | 정답 증상 코드. 판단할 수 없으면 비운다 |
| onset | 정답 발생 시점 |
| status | 정답 작동 상태(`완전히 멈춤`, `느리지만 작동`, `정상 작동`) |
| ask | 챗봇이 되물어야 하는 항목. 여러 개면 `;`로 구분한다 |
| note | 판단 기준 메모 |

## 작성 규칙

- 문장은 현장에서 급하게 보내는 말투로 쓴다. 맞춤법과 띄어쓰기를 일부러 다듬지 않는다.
- 문장에 없는 정보는 정답에도 넣지 않고, 되물어야 하는 항목으로 둔다.
- 알람 번호의 뜻은 정답에서도 짐작하지 않는다. 분류표에 이름이 없는 알람은 '종류를 모른다' 코드로 둔다.

## 긴급도

긴급도는 LLM이 정하지 않는다. 접수자가 말한 작동 상태로 정한다.

| 작동 상태 | 긴급도 |
|---|---|
| 완전히 멈춤 | 높음 |
| 느리지만 작동 | 중간 |
| 정상 작동 | 낮음 |
