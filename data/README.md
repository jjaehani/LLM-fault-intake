# 가상 증상 데이터

LLM이 접수 항목을 제대로 뽑는지 시험하기 위한 데이터다. 모든 문장은 직접 지어서 만들었다.

## 작성 규칙

- 실제 업체의 수리 내역, 고객 문의, 장비 모델명은 쓰지 않는다.
- 장비는 프레스, 컨베이어처럼 일반 명칭만 쓴다.
- 문장은 현장에서 급하게 보내는 말투로 쓴다. 맞춤법과 띄어쓰기를 일부러 다듬지 않는다.
- 문장에 없는 정보는 정답에도 넣지 않고, 되물어야 하는 항목으로 둔다.

## 파일

`symptoms.csv`의 각 행은 접수자가 처음 보내는 메시지 하나와 그 정답이다.

| 열 | 내용 |
|---|---|
| id | 문장 번호 |
| type | `intake`(접수) 또는 `off_topic`(범위 밖 질문) |
| utterance | 접수자가 처음 보내는 문장 |
| equipment | 정답 장비 종류. 문장에 없으면 비운다 |
| symptom | 정답 증상 |
| onset | 정답 발생 시점 |
| status | 정답 작동 상태(`완전히 멈춤`, `느리지만 작동`, `정상 작동`) |
| ask | 챗봇이 되물어야 하는 항목. 여러 개면 `;`로 구분한다 |
| note | 판단 기준 메모 |

## 긴급도

긴급도는 LLM이 정하지 않는다. 접수자가 고른 작동 상태로 정한다.

| 작동 상태 | 긴급도 |
|---|---|
| 완전히 멈춤 | 높음 |
| 느리지만 작동 | 중간 |
| 정상 작동 | 낮음 |
